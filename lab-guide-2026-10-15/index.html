이 지침서는 중학교 과학 조작형 가상실험실을 만들고, GitHub Pages에 올려 학생에게 나눠 줄 웹주소까지 제공하는 전 과정을 정리한 것입니다. (2026. 10. 15. 기준)

중학교 과학 교사(이재광)가 태블릿으로 학생에게 배포하는 조작형 가상실험실을 만드는 지침이다. 학생은 웹주소 하나만 열면 "왜 그런지 이해 → 직접 조작하며 확인 → 스티커로 개념 정리 → 내 삶과 연결 → 배운 것 확인"까지 끝낼 수 있어야 한다. 정보를 나열하는 슬라이드가 아니라, 학생이 값을 바꾸고 누르고 붙이며 결과를 관찰하는 경험이 핵심이다.

작업의 끝은 "학생에게 바로 나눠 줄 수 있는 웹주소"다. 제작 → 검증 → GitHub 업로드 → 게시 확인 → 웹주소 제공까지 한 번에 진행한다.

0. 확인 → 1~4. 제작 → 5. 검증 → 6. GitHub 배포·웹주소 확인 → 7. 전달과 기록

0. 시작 전에 확인할 것

대화·메모리·프로젝트 문서에 이미 있으면 다시 묻지 않는다. 없으면 한 번에 짧게 묻는다. 프로젝트에 교과서·지도서 PDF가 있으면 해당 차시 쪽을 먼저 읽고 반영한다.

  1. 학년 / 단원 / 차시 주제 — 예: "1학년 Ⅳ단원 입자의 운동과 물질의 상태"
  2. 교과서와 쪽수 — 기본은 미래엔. 교과서 탐구·[해 보기] 활동명과 쪽수, 지도서 쪽수를 알면 그대로 반영한다.
  3. 성취기준 — 예: [9과12-03]. 모르면 교육과정에서 해당 성취기준을 찾아 도입 화면에 적는다.
  4. 교과서 붙임딱지(스티커) 활동 여부 — 교과서 부록 붙임딱지를 쓰는 활동이 있으면 그것을 스티커 단계로 재현한다. 없으면 이 지침의 "스티커 판 유형"에서 단원에 맞는 것을 골라 설계한다.
  5. 학생들이 어려워하는 부분 / 지도서 오개념 — 개념 단계와 스티커 단계에서 공들여 다룬다.
  6. 출판사 표기 — 기본은 교과서·지도서 쪽수 배지를 넣는다. 사용자가 "출판사명은 넣지 말고"라고 하면 출판사명과 쪽수를 모두 빼고 성취기준만 표시한다. 용어가 교과서마다 다르면 함께 적는다(예: 허파순환(폐순환이라고도 해요)). 쪽수는 제작 노트에만 남긴다.

교과서 실험명을 정확히 모르면 해당 개념의 표준 실험을 기본값으로 삼고, 어떤 실험을 기준으로 했는지 결과 보고에서 밝힌다.

GitHub 배포는 따로 묻지 않고 기본으로 진행한다. 사용자가 "파일만 줘", "올리지 마"라고 하면 6장을 건너뛴다.

1. 결과물 구조 — 6단계 (반드시 이 순서)

단일 HTML 파일에 아래 6단계를 담는다. 상단 스텝 인디케이터(6칸, 단계 이름 표시)로 현재 위치를 보여준다. 결과 화면은 인디케이터에서 제외한다.

단계 화면 id 내용
1. 도입 screen-intro 단원·차시 제목, 교과서 쪽수·성취기준, 학습목표 2~3개, 생각 열기, "시작하기"·"이어서 하기"
2. 개념 screen-concept 핵심 아이디어 박스 + 개념 아코디언 카드 + 오개념 바로잡기
3. 탐구 screen-experiment 탭: 탐구 계획서 / 가상실험(필요 시 실험 탭 여러 개)
4. 스티커 붙이기 screen-sticker 붙임딱지를 골라 개념 판의 빈칸에 붙여 정리, 확인·재도전
5. 실생활 screen-life 일상 사례 카드 6~8개
6. 개념 확인 screen-quiz → screen-result 10문항, 즉시 해설, 오답 재도전, 자가 점검

모든 화면 하단 푸터에 작게 "Made by Lee Jae Kwang".

1단계 도입

  • 제목, 한 줄 소개, 교과서 쪽수 / 지도서 쪽수 / 성취기준 배지 (0-6 출판사 표기 규칙을 따른다)
  • 학습목표 2~3개 ("~을 설명할 수 있다" 형태)
  • 이번 시간 흐름 미리보기(6단계 아이콘 한 줄)
  • 교과서 "들어가기" 질문이 있으면 생각 열기 카드(입력칸 + 예시 답안 보기)로 넣는다.
  • 진행 위치를 localStorage에 저장하고 "이어서 하기" 버튼을 둔다.

2단계 개념

  • 핵심 아이디어(필수): 화면 맨 위, 눈에 띄는 박스에 이 차시의 큰 개념을 1~2문장으로. 모든 실험실에 반드시 넣는다.
  • 개념(필수): 아코디언 카드로 하나씩 연다. 교과서 문장 복사가 아니라 "왜 그런가"를 비유·SVG 그림·Canvas 애니메이션으로 설명한다. 그림은 부분을 탭하면 설명이 나오는 방식이 좋다.
  • 오개념 바로잡기: 지도서가 짚은 오개념을 "❌ 흔한 생각 → ✅ 실제로는" 카드로. (예: 융해 vs 용해, 김은 수증기가 아니다, 식물은 밤에 광합성하지 않는다, 심장 소리는 판막이 닫히는 소리다)

3단계 탐구

  • 탐구 계획서 탭: 문제 인식 → 가설 → 변인(조작·통제·종속) → 준비물 → 실험 과정(단계별) → 예상 결과. 학생이 가설·예상 결과를 직접 입력할 칸을 둔다(자동 저장).
  • 가상실험 탭: 교과서 실험 장치를 SVG/Canvas로 그리고, 조작하면 같은 화면에서 즉시 결과가 바뀌게 한다.
  • 변수 조절형(슬라이더) / 배치·연결형 / 단계 진행형(버튼) / 비교 관찰형(대조군·실험군) 중 골라 쓴다.
  • 시작·일시정지·초기화, 실험 기록표, 조건별 결과 그래프 겹쳐 보기를 기본으로 한다.
  • 관찰 기록 입력칸 (localStorage 저장).
  • 교과서 범위를 넘는 수치·조작은 "확장" 배지와 "가상 값" 안내를 붙인다. 지도서가 "다루지 않는다"고 한 원리는 넣지 않는다.
  • 시뮬레이션 모델은 과학적으로 타당한 식으로 만들고, 교과서 결과와 같은 경향이 나오는지 확인한다. 핵심 조건별 예상 수치를 표로 뽑아 두면 제작 노트에 그대로 쓸 수 있다.

4단계 스티커 붙이기 (정리 활동)

교과서의 붙임딱지 활동을 디지털로 재현한 단계다. 학생이 개념과 실험 결과를 스스로 "붙여서" 정리하게 해, 읽고 넘어가는 대신 한 번 더 판단하게 만든다. 자세한 설계는 아래 2장을 따른다.

5단계 실생활

  • 6~8개 사례 카드. 학생이 "아, 그거였구나" 할 수 있는 구체적 장면 (예: 급식실 냄새가 교실까지 오는 이유, 겨울 비닐하우스 보광).
  • 각 카드 끝에 "이 단원의 어떤 개념?" 한 줄 연결.

6단계 개념 확인 10문항

  • 개념이해형·적용형·자료해석형(그래프·표·그림)·통합형을 섞는다. 스티커 단계에서 정리한 내용과 가상실험 결과를 묻는 문항을 1~2개씩 넣는다.
  • 문제 순서·보기 순서 무작위, 선택 즉시 정답/오답 + 해설, 틀린 문제만 다시 풀기.
  • 결과 화면: 점수, 걸린 시간, 틀린 문제 목록, 격려 메시지, 학습목표 자가 점검 체크리스트("이제 나는 ~할 수 있다"), 캡처해 제출하라는 안내.

2. 스티커 붙이기 단계 설계

2-1. 스티커 판 유형 (단원에 맞게 하나 이상 선택)

유형 판의 모습 적합한 단원 예
그림 이름표형 SVG 그림(기관·장치·모형) 위 빈 칸에 이름 스티커 식물 구조, 심장·혈관 모식도, 눈·귀 구조, 실험 장치 이름
순서 배열형 1→2→3→4 빈 칸에 과정 스티커 광합성 산물의 생성→이동→저장→사용, 혈액 순환 경로
분류판형 2~5개 칸(예: 융해·응고·기화·액화·승화)에 현상 스티커 상태 변화, 물리변화/화학변화, 원소/화합물
표 채우기형 비교표의 빈 셀에 스티커 고체·액체·기체 성질 비교, 동맥·모세혈관·정맥 비교
관계도형 원인→결과 화살표 도식의 빈 칸 빛의 세기↑ → 광합성량↑ → CO₂↓
실험 결과형 실험에서 얻은 결과 그래프·표 옆에 결론 스티커 보상점·광포화점 찾기, 온도와 확산 속도

교과서에 붙임딱지 활동이 있으면 그 판 모양과 딱지 문구를 최대한 그대로 따른다. 내용이 많으면 판을 2~4개로 나누고, 앞 판을 완성해야 다음 판이 열리게 한다.

2-2. 스티커 구성 원칙

  • 판마다 스티커 6~12장. 정답 스티커 + 오개념 함정 스티커 1~3장(예: '용해'를 상태 변화 판에 섞기). 함정은 어디에도 붙지 않는 게 정답이다.
  • 스티커 문구는 짧게(2~8자). 설명형이면 한 줄 이내.
  • 스티커 모양은 둥근 모서리 + 살짝 그림자 + 약간의 기울기(−3°~3°)로 "딱지" 느낌을 준다. 색은 개념 범주별로 구분하되, 색만으로 구분하지 않고 아이콘/글자도 함께 쓴다(색약 배려). 함정 스티커는 정답 스티커와 같은 색으로 한다.

2-3. 조작 방식 (태블릿 우선)

  • 기본은 "탭해서 고르고 → 빈칸 탭해서 붙이기". 고른 스티커는 들어 올린 효과(확대·그림자·테두리)로 표시하고, 붙일 수 있는 빈칸은 점선 테두리로 강조한다.
  • 드래그 앤 드롭은 보조로만 제공한다(Pointer Events 사용, 스크롤과 충돌하지 않게 touch-action:none은 드래그를 쓸 때만 스티커에).
  • 이미 붙은 스티커를 다시 탭하면 떼어져 스티커 보관함으로 돌아간다.
  • 빈칸에 이미 스티커가 있으면 새 스티커로 교체하고 기존 것은 보관함으로 돌려보낸다.

2-4. 확인과 피드백

  • "확인하기" 버튼을 눌러야 채점한다(붙이는 즉시 정답을 알려주지 않는다 → 학생이 끝까지 스스로 판단).
  • 맞은 칸: ✔ 표시 + 고정. 틀린 칸: ✖ 표시 후 0.8초 뒤 스티커가 보관함으로 돌아가고, 해당 칸에 단계적 힌트(1차: 개념 단서, 2차: 실험 결과 단서)를 보여준다. 그림 위 빈칸이 작으면 힌트는 아래 메시지 영역에 기호별로 보여준다.
  • 모두 맞히면 완성된 정리판을 크게 보여주고 "완성!" 도장 효과 + 한 줄 요약. 이 완성판이 곧 학생의 개념 정리 노트가 된다.
  • 상단에 "붙인 스티커 n / 전체", "시도 횟수"를 표시한다.
  • 붙인 상태는 localStorage에 저장해 새로고침해도 유지한다. "처음부터 다시" 버튼도 둔다.

/* 단원별로 이 두 배열만 교체한다. answer:null 인 스티커는 오개념 함정 */
const STICKERS = [ {id:'s1', label:'융해', answer:'a'}, {id:'s9', label:'용해', answer:null} /* … */ ];
const SLOTS    = [ {id:'a', title:'고체 → 액체', hints:['열을 흡수해요','얼음이 녹는 현상']} /* … */ ];
const STK_KEY = 'vlab-sticker-[단원코드]';
let picked = null, placed = {}, tries = 0, hintLv = {};

function loadStk(){ try{ const s=JSON.parse(localStorage.getItem(STK_KEY)||'{}'); placed=s.placed||{}; tries=s.tries||0; }catch(e){} }
function saveStk(){ try{ localStorage.setItem(STK_KEY, JSON.stringify({placed,tries})); }catch(e){} }

function renderStickers(){
  const used = new Set(Object.values(placed));
  const tray = document.getElementById('stkTray'); tray.innerHTML='';
  STICKERS.filter(s=>!used.has(s.id)).forEach((s,i)=>{
    const b=document.createElement('button'); b.className='sticker'+(picked===s.id?' picked':'');
    b.style.setProperty('--tilt', ((i%5)-2)*1.2+'deg'); b.textContent=s.label;
    b.onclick=()=>{ picked = picked===s.id?null:s.id; renderStickers(); };
    tray.appendChild(b);
  });
  SLOTS.forEach(sl=>{
    const el=document.getElementById('slot-'+sl.id); el.classList.toggle('ready', !!picked);
    const s=STICKERS.find(x=>x.id===placed[sl.id]);
    el.innerHTML = s ? '' : `<span class="hint">${hintLv[sl.id]?sl.hints[hintLv[sl.id]-1]:''}</span>`;
    if(s){ const b=document.createElement('button'); b.className='sticker'; b.textContent=s.label;
           b.onclick=e=>{ e.stopPropagation(); delete placed[sl.id]; el.classList.remove('ok','no'); saveStk(); renderStickers(); };
           el.appendChild(b); }
    el.onclick=()=>{ if(!picked) return; placed[sl.id]=picked; picked=null; el.classList.remove('ok','no'); saveStk(); renderStickers(); };
  });
  const need = STICKERS.filter(s=>s.answer).length;
  document.getElementById('stkCount').textContent = Object.keys(placed).length+' / '+need;
  document.getElementById('stkTry').textContent = tries;
}

function checkStickers(){
  tries++; let allOk = true;
  SLOTS.forEach(sl=>{
    const el=document.getElementById('slot-'+sl.id), s=STICKERS.find(x=>x.id===placed[sl.id]);
    const ok = !!s && s.answer===sl.id; el.classList.toggle('ok', ok); el.classList.toggle('no', !!s && !ok);
    if(!ok){ allOk=false; hintLv[sl.id]=Math.min((hintLv[sl.id]||0)+1, sl.hints.length);
             if(s) setTimeout(()=>{ delete placed[sl.id]; el.classList.remove('no'); saveStk(); renderStickers(); }, 800); }
  });
  saveStk(); renderStickers();
  if(allOk){ document.getElementById('stkNext').style.display='inline-block'; /* 완성판 강조 + '완성!' 도장 효과 */ }
}
function resetStickers(){ placed={}; tries=0; hintLv={}; picked=null; saveStk();
  document.querySelectorAll('.slot').forEach(e=>e.classList.remove('ok','no')); renderStickers(); }

3. 디자인 원칙 (태블릿, 세련되고 깔끔하게)

  • 터치 우선: 버튼·슬라이더·스티커 최소 48px. hover에만 의존하는 상호작용 금지.
  • 과밀 금지: 세로·가로 모두 고려한 여백과 카드 레이아웃. 교실 뒷자리에서도 읽히는 글자 크기. Canvas 글자는 휴대폰 폭에서 줄어드는 것을 고려해 크게(26px 이상) 그린다.
  • 일관된 색·타이포: 6단계 모두 같은 팔레트·폰트·아이콘. 한글은 Noto Sans KR 계열(시스템 폰트 폴백, 외부 폰트 로딩 없이도 깨지지 않게).
  • 의미 있는 색 체계: 단원 개념과 연결된 색을 쓴다(예: 온도 → 차가운 파랑~뜨거운 주황, 산소 많은 혈액 빨강 / 적은 혈액 파랑).
  • 움직임에는 의미를: 장식 애니메이션보다 조작 결과를 이해시키는 전환(그래프가 부드럽게 갱신, 스티커가 제자리로 돌아감).
  • 색약 배려: 정답/오답·상태를 색만으로 구분하지 않고 ✔✖ 아이콘과 글자, 실선/점선을 함께.
  • assets/template.html이 있으면 CSS 변수와 구조의 출발점으로 삼고, 없으면 2-5 뼈대와 이 원칙으로 직접 구성한다.

4. 구현 기준

  • 단일 HTML 파일(CSS/JS 인라인), 프레임워크 없이 순수 HTML/CSS/JS. 보통 60~140KB.
  • 외부 의존 0, 완전 오프라인 동작 — 학교 네트워크와 무관하게 동작하고 GitHub Pages에 그대로 올라간다.
  • 그림은 SVG(개념 도식·실험 장치·스티커 판), 움직이는 입자·시뮬레이션은 Canvas 2D. 같은 그림을 개념·실험·스티커에서 함께 쓰면 SVG 생성 함수를 하나로 만들어 재사용한다.
  • 외부 이미지 임베드 금지(저작권). 사진이 필요하면 출처 안내만.
  • localStorage로 관찰 기록·스티커 상태·진행 위치 저장(키 접두어 vlab-[단원코드]-, 항상 try/catch로 감싸 저장이 막혀도 동작).
  • 코드 골격 재사용: goTo() 화면 전환 + 스텝 인디케이터, 탭, 관찰 기록 저장, STICKERS/SLOTS(또는 BOARDS) 배열, QUIZ 배열. 새 단원은 실험 로직·스티커 배열·문항 배열만 교체한다.

5. 검증 (배포 전 필수)

Playwright(설치된 Chromium 사용, playwright install 금지)로 자동 검증한다. 검증을 통과해야 6장 배포로 넘어간다.

  1. 뷰포트 3종: 태블릿 세로(768×1024), 태블릿 가로(1180×820), 휴대폰(390×844)
  2. 6단계 모든 화면·모든 탭을 실제로 클릭해 이동
  3. 가상실험: 슬라이더·버튼 조작 후 결과 값이 예상 경향(제작 노트 표의 값)과 맞는지 확인
  4. 스티커: 정답 배치 → 확인 → 완성 표시 / 오답 배치 → ✖ 후 보관함 복귀·힌트 표시 / 함정 스티커가 보관함에 남아도 완성 처리되는지 / 새로고침 후 상태 유지
  5. 퀴즈: 10문항 끝까지 풀기, 오답 재도전 동작
  6. 콘솔 오류 0건, 가로 스크롤 없음
  7. 주요 화면 스크린샷을 직접 보고 겹침·잘림 확인

6-2. 폴더 이름 정하기

  • 영어 소문자 + 하이픈(kebab-case), 차시 주제를 나타내는 2~3단어. 예: circulatory-system, digestive-system, nutrients, phase-change, force-equilibrium, photosynthesis-light.
  • 한글·공백·대문자 금지(주소가 깨지거나 학생이 입력하기 어렵다).
  • 같은 이름 폴더가 이미 있으면:
  • 같은 실험실의 수정본 → 그 폴더의 index.html을 덮어쓴다. 웹주소가 그대로 유지되어 학생에게 다시 안내할 필요가 없다.
  • 다른 실험실 → -2를 붙이지 말고 더 구체적인 이름을 짓는다(예: photosynthesis → photosynthesis-storage).
  • 저장소 루트의 기존 파일(과학실험실.html 등)과 다른 폴더는 건드리지 않는다.

6-3. 올리는 절차

  1. 저장소 연결 — add_repo(owner abio6883-ctrl, repo JKscience, access push). 미리 curl·gh repo view로 존재 여부를 확인하지 않는다.
  2. 복제 — 한 번만, 넉넉한 시간 제한(약 10분)으로: git clone --depth 1 https://github.com/abio6883-ctrl/jkscience /home/claude/jkscience 이미 복제본이 있으면(git -C /home/claude/jkscience rev-parse HEAD 성공) 다시 복제하지 않고 그대로 쓴다.
  3. 파일 배치 — mkdir -p <폴더명> && cp <완성본>.html <폴더명>/index.html
  4. 커밋 — 새 실험실은 Add <실험실 이름> 가상실험실 (중<학년> <단원>), 수정본은 Update <실험실 이름> 가상실험실: <바뀐 점>. 세션이 지정한 attribution 줄을 메시지 끝에 붙인다. git -c user.name="abio6883-ctrl" -c user.email="abio6883@gmail.com" commit -m "..."
  5. 푸시 — 최신 상태에 맞춘 뒤 main에 바로 올린다: git fetch origin main && git rebase origin/main && git push origin HEAD:main
  6. 게시 확인 — GitHub Pages 반영에 1~2분 걸린다. 작업 환경의 셸은 github.io에 접속할 수 없으므로 curl이 아니라 WebFetch로 웹주소를 열어 페이지 제목이 실험실 제목과 같은지 확인한다. 404거나 이전 버전이면 1분 기다렸다 한 번 더 확인한다.
  7. 웹주소 제공 — 확인된 주소를 결과 보고의 맨 앞에 굵게 적는다.

6-4. 문제가 생기면

  • add_repo 권한 오류 → 도구가 알려준 이유를 그대로 전하고(GitHub 연결은 claude.ai 설정의 커넥터에서), 파일 전달과 미리보기까지만 하고 마친다. 같은 저장소로 재시도하지 않는다.
  • clone·push 중 HTTP 429 → 이 세션의 동시 작업 제한이다. 10초 기다렸다 한 번만 다시 시도한다.
  • push가 413으로 거부 → git fetch origin main 후 rebase하고 다시 push한다.
  • 두 번 확인해도 404 → 업로드는 됐으니 저장소 Settings → Pages에서 main / (root) 게시가 켜져 있는지 확인해 달라고 안내한다.
